## 検証

- 変更したC# 14ファイルをRoslynで構文解析し、構文エラー0件。
- `git diff --check`で差分の空白エラーなし。
- Unity 6000.0.41f1のバッチ起動を試したが、ユーザーキャッシュのデータベースへのアクセスに失敗し、コンパイル開始前にクラッシュした。終了コードは0だったが成功とは扱っていない。
- Unityコンパイル、Fusionのコード生成、ホスト・クライアントでのプレイ検証は未完了。構文解析はそれらの代替ではない。

## Unityで確認する手順

1. ホスト＋クライアントでハタノを生成し、開始時の手・腰・背中の武器配置を相互確認する。
2. 双方で二丁拳銃⇔レーザーを切り替え、相手側にも切替モーションが表示されることを確認する。切替中の移動停止と、終了・被ダメ中断後の移動復帰を確認する。
3. 構えを保持して切替、切替途中で構え解除、切替後の最初の構えを双方で試す。カメラ・照準・射撃・武器別ポーズが整合することを確認する。
4. Ultの開始・構え・発射終了まで、エイム・武器切替・近距離インタラクトを試す。エイムとUltの同時押しも確認する。
5. 展示物へのマウント中に構えキーを押し、照準UIが出ないことを確認する。
6. 二丁拳銃で空中・壁・対象へ長押し射撃し、各発射の攻撃モーションと例外がないことを確認する。
7. 構え中に前後左右へ移動・回避し、補間と回避方向をホスト・クライアント双方で確認する。
8. エクスカリバー装備中、ハタノの構え中は近接攻撃できず、構え解除後は攻撃できることを確認する。

## 続けるために必要な情報

- スタミナ：ダッシュ用／回避用のどちらか、どう異常になるか、再現操作。
- 足滑り：該当武器・移動方向と、エイム移動クリップの実体・想定速度。
- 持ち替え：切替クリップの実体と、手から外す／持つイベントの意図した時刻。
- ロケットの向き：再現操作、該当Timeline・クリップ・ソケット設定を含むアセット。

## 追加変更：全必殺技中のインタラクト制限

- `AbilityUltBase` が開始時に `SetInteractionBlocked(true)`、能力終了処理の `finally` で `false` を通知する。カットイン終了時の移動制限解除とは独立させる。
- `PlayerInteractionController` は汎用の同期状態 `IsInteractionBlocked` を持ち、ハタノ固有クラスを参照しない。更新・入力・遠距離処理・完了処理・ホスト側RPCで制限を確認する。
- 制限開始時は進行中の近距離／遠距離インタラクトを中断し、所有クライアントのUIを非表示にする。必殺技終了後は進行度0から再開する。
- 対象：ハタノ、オカベ、オオクボ、サルトビ、タニヒラ、ハルク、タカムラの擬態を含む `AbilityUltBase` の全派生クラス（コード上は7クラス）。
- 追加変更のC# 2ファイルはRoslyn構文解析でエラー0件、`git diff --check`も通過。Unityコンパイル・通信プレイは前述の環境制約により未検証。
- 再現確認：各必殺技のカットイン中・効果中にインタラクトを試し、ホスト／クライアント双方で拒否されること。進行途中で必殺技を開始した場合はUI・進行がリセットされ、必殺技終了後に通常のインタラクトが可能になること。特にカットイン終了後に移動可能となる必殺技でも、インタラクトだけは終了まで制限されること。

## 追加変更：PlayerManagerのキャラ固有依存を除去

- `PlayerManager` から `HatanoAbilityStatusManagement` の参照・取得・状態判定を削除した。
- 汎用の同期状態 `IsMovementInputBlocked` と、状態権限側で設定する `SetMovementInputBlocked` を追加した。移動・ダッシュ・ジャンプ・回避の入力抑止範囲は従来の武器切替時と同じ。
- ハタノ側が切替モーション開始時に制限を設定し、完了・中断・例外時の `finally` で解除する。既存の攻撃処理が使用する `IgnoreMoveInput` / `IgnoreEvasionInput` は書き換えない。
- 変更したC# 2ファイルの構文解析と差分チェックを実施。Unityコンパイル・通信プレイは未検証。切替中の移動停止と、正常終了・被ダメ中断後の移動復帰をホスト／クライアントで確認する必要がある。
